# Taste — General Preferences
- Prefers written deliverables as LaTeX `.tex` files formatted for IEEE publication (IEEEtran, conference style). Confidence: 0.85
- When producing a new document, wants the output to match the format/structure of an existing reference/template file ("like sample.tex") rather than an arbitrary layout. Confidence: 0.6
- Cares strongly about research/output quality and rigor — expects careful, high-quality work rather than quick drafts. Confidence: 0.6
- When writing a paper modeled on a reference paper, wants a genuinely novel architecture/contribution ("similar but different"), not a close reproduction of the source. Confidence: 0.6
- Wants papers to include results/analysis figures (plots, charts) pulled from the actual experimental data to make the work more compelling than text and tables alone. Confidence: 0.6
- Prefers figures to be generated programmatically from a runnable Python script (e.g., a `.py` that emits images) rather than hand-made, and expects the script to be run to produce them. Confidence: 0.7
- Wants image files embedded by reference inside the document at the corresponding location (Markdown `![](path)` / `\includegraphics`), not just produced as loose files. Confidence: 0.55
- Prefers generated/derived output written to a NEW file (e.g., a separate `*_illustrated.md`) rather than overwriting the original source document. Confidence: 0.5
- Wants figures delivered as raster image files (e.g., high-resolution PNG) rather than PDF/vector or live TikZ, and expects `\includegraphics` to point at those image files. Confidence: 0.6
- Prefers concrete quantitative content over empty placeholders in drafts — when a table has TBD/blank fields, wants it filled with real, "reliable" values sourced from published research (with citations), not left empty; this extends to cells describing their own not-yet-run system, where they ask for values "based on other research" to stand in until the experiment is done. Confidence: 0.7
- When revising a manuscript toward IEEE-conference readiness, expects rigorous fixes: every citation must actually support the claim it is attached to (mismatched citations rejected), duplicate references removed, and unsupported/fabricated statistics replaced with qualitative statements. Confidence: 0.6
- Wants figures whose underlying values are illustrative or synthesized to be explicitly labelled as such (in the caption and surrounding prose) rather than presented as measured results. Confidence: 0.55
- Wants papers to contain the scholarly scaffolding IEEE reviewers expect — explicit theoretical grounding (named, cited theories) and a dedicated limitations/future-work section. Confidence: 0.55
- For AI/ML papers, wants the methodology to include formal IEEE-style content — numbered equations and algorithm pseudo-code — not prose alone. Confidence: 0.5
- Supplies detailed paper feedback as a `feedback.md` file stored alongside the manuscript and expects each point in it to be read and addressed. Confidence: 0.55
- When asked to "give feedback" on a paper, wants a critical reviewer-style assessment (major/minor weaknesses, gaps, rejection risks, "why accept this") produced first, before implementing revisions — review pass then edits, not silent changes. Confidence: 0.5
- Prefers the agent to look up and fill in missing/verifiable information itself via web search rather than leaving placeholders/flags for the user to resolve — told the agent to "search online" instead of leaving incomplete reference metadata flagged for author input. Confidence: 0.65
- Expects the compiled PDF to have a working hyperlink layer: in-text citations (`\cite`) must be clickable and jump to their bibliography entry, cross-references jump to their targets, and DOI/URL strings open externally (i.e., `hyperref` enabled, DOIs wrapped in `\url{}`). Confidence: 0.7
- Does not want bracketed placeholder/flag markers (e.g. `[AUTHOR INPUT REQUIRED: ...]`, `[NEEDS EVIDENCE]`, `[REFERENCE VERIFICATION REQUIRED]`) visible anywhere in the compiled/rendered deliverable — including legend/notes sentences in the bibliography, not just inline stubs; unfinished notes and residual explanations should be moved to source comments or a separate tracking file, leaving only a minimal plain-text marker (e.g. a `†` superscript) plus a short clean legend. Confidence: 0.8
